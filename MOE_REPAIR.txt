WHAT WAS FAILING

The original MoE replaced the cross-encoder's relevance score with similarity
between learned fusion vectors. It could promote unrelated evidence above a
strong cross-encoder match. In the saved 100 text questions, 59 baseline hits at
rank 3 became misses, while only one miss became a hit. The reader then often
received worse evidence, or selected a confident answer from a distractor.

The training signal is also limited: 300 source-derived training examples and
60 development examples. These are weak labels, not a large expert-annotated
question-answer training set. This evidence explains the observed ranking
failures; it does not prove that model capacity alone caused them.

WHAT CHANGED

1. Retrieval still searches DOSA, SCALE, DRISHTIKON, DIWALI and Indian Cultural
   Dataset. The shared cross-encoder returns 12 candidates by default.
2. The repaired text score retains cross-encoder relevance:

       s(d) = z(cross_encoder_score(d)) + 0.25 * z(MoE_cosine(d))

   z standardizes scores within the same candidate pool, using population
   standard deviation with a minimum denominator of 0.000001.
3. A conservative rule protects the baseline's top-3 and top-6 evidence sets.
   Within the rank bands 1–3, 4–6 and 7–12, MoE may reorder only near-tie groups
   spanning at most 0.05 standardized cross-encoder score units in total.
   A chain of adjacent near ties cannot create a wider group.
4. The reader receives the same evidence as the baseline. Baseline order is
   restored for reader tie handling, so identical confidence scores cannot
   change the answer merely because MoE changed the display order.
5. Image-only results use CLIP baseline fallback, explicitly reported as such.
   This release does not claim that image MoE has improved.

MoE is active for text: its weight is 0.25 and the selected checkpoint is trained.
In the saved benchmark it changed the full order for 69/100 text questions,
including the top-3 order for 6 and top-6 order for 27. Evidence membership did
not change. The simple fusion condition selected weight zero and is explicitly
a baseline fallback; it is not a successful learned-reranker improvement.

This is a conservative hybrid with MoE, not the original fusion-only method.
Because the evidence is protected, equal answer accuracy is expected by design.
It is useful as a working repair, but not evidence of MoE superiority for a paper.
Printed residual scores need not decrease globally: the evidence/near-tie
constraints take precedence over unrestricted sorting by that score.
These ranking scores are not percentages or probabilities. The separately printed
answer-confidence score comes from the reader and is not a calibrated guarantee
that the answer is correct.

TRAINING AND SELECTION

The experiment tried listwise training for both simple fusion and MoE, using
the existing 300 training anchors, fresh or existing initialization, 20 epochs,
AdamW at 0.0001, and temperatures 0.05 or 0.1. Diagnostic development shortlists
initially contained an injected positive; those are clearly labelled diagnostic.
Final selection used actual global retrieval for 60 development questions,
without injecting positives. Both model kinds had the same parameter search.

The conservative selector requires a development MRR improvement and no
individual labelled-rank regression, then prefers smaller near-tie spans and
weights. The selected MoE improved development MRR from 0.9417 to 0.9500, with
one known positive moving from rank 2 to rank 1. This is selection evidence,
not independent evaluation evidence. Development query expansion was off;
the 120-question benchmark uses the existing cached API expansions.

The selected model is:

Its selection, SHA-256 fingerprint and parameters are recorded in:
experiments/moe_release/conservative_selection.json
All tried conservative settings remain in conservative_development_results.json.

RUN QUESTIONS

Open a terminal and enter:

    cd "."

Compare the same question with identical settings:

    ./venv/bin/python main_without_moe.py --ask "Which beach in Visakhapatnam is described as a venue for Navy air shows?" --candidate_k 12 --top_k 3 --enable_images
    ./venv/bin/python main_with_moe.py --ask "Which beach in Visakhapatnam is described as a venue for Navy air shows?" --candidate_k 12 --top_k 3 --enable_images

Change --top_k 3 to --top_k 6 for six pieces of evidence. Both launchers now
default to 12 candidates and final top 3. Query expansion remains ON. Existing
benchmark expansions are cached. New questions may call the configured Groq API.
For an offline comparison, add --no_query_expansion to BOTH commands.

For text features only, omit --enable_images from BOTH commands. For image-only
retrieval, run:

    ./venv/bin/python main_with_moe.py --image_query "Find Shondol dancers performing outdoors in Ladakh." --output my_image_results.csv

That command prints the CLIP fallback notice and records moe_rescore_used=False.

RUN YOUR OWN VALIDATION

    ./venv/bin/python validation_conservative.py --suite validation_queries_120.json --candidate_k 12 --output_dir my_validation_conservative

This runs real retrieval and reader inference for 100 labelled text questions
and 20 image queries, with matched candidate pools, phrasings, image settings,
reader outputs, and final K=3/K=6 across all three conditions. It checks source,
split and checkpoint fingerprints. All five datasets remain searchable.

For a quick two-question check, append --max_queries 2. For an offline run,
append --no_query_expansion; keep those results separate from expanded runs.
--text_only masks text-reranker image features; image tasks still use CLIP.

Results are saved in the output folder:
  validation_matrix.csv  — metrics by condition, dataset and modality
  per_question.csv       — each answer, evidence ranking, status and metrics
  validation_report.json — full rankings, settings, provenance and errors
  paired_differences.csv — paired source-group bootstrap intervals

The metrics include Hit/Recall/Precision@3 and @6, MRR, nDCG, answer Exact Match,
answer token F1, evidence coverage, and measured processing time components.
Only known positive evidence is labelled; Precision/Recall/nDCG do not represent
exhaustive relevance judgements across the entire corpus. No-answer results stay
in the evaluation; model/reader exceptions are visibly flagged as errors.
