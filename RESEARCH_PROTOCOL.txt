CulturalQA experimental protocol

Conditions and controlled variables

without_moe: global FAISS + BM25 retrieval, cached text query expansion, cross-
encoder ranking, then the requested K contexts and the shared extractive reader.
simple_fusion: the same cross-encoder shortlist, rescored by one trained network
using the same BERT/CLIP features as MoE. It has 1,214,336 trainable parameters.
with_moe: the same shortlist, rescored by shared concatenation plus two gated
routed experts. It has 1,200,451 trainable parameters. The difference is about
1.16%, so the single-network comparison also controls approximate model size.

Both models use frozen BERT and CLIP encoders, the same 300 weakly labelled
training triplets, seed 42, batch size 32, Adam learning rate 0.001, eight epochs,
and triplet margin 0.2. MoE additionally uses its architecture-specific load-
balancing regularizer with coefficient 0.01. Positive AND negative candidates use
their own image when available. Missing or explicitly masked images receive zero
features. This removes the former unconditional blank-negative-image shortcut.

Checkpoints are selected by minimum triplet hinge loss on development examples,
not by test results. Development pairwise accuracy is a training diagnostic;
it is not retrieval/QA accuracy. The checkpoint envelopes and JSON sidecars
record data/split hashes, train references, query hashes, architecture source
hashes, encoder revisions, versions, parameter counts and selection epoch.

Split and searchable knowledge

All 74,528 active raw records are assigned to seeded train/development/test groups,
initially about 70/15/15 percent of groups per dataset. Shared artifact/concept
names, SCALE terms, exact Indian Cultural text, and image groups stay together.
Exact image-byte aliases are merged. Groups containing a held-out alias are
promoted to the furthest-held-out fold. The measured final counts and approximate
ratios are in split_manifest.json; they need not be exactly 70/15/15 after merging.

The image audit found 1,549 file paths but 1,536 distinct image contents. Eight
identical-content groups initially spanned folds. The corrected split has zero
such cross-fold groups. It uses exact bytes, not a guarantee that visually similar
or semantically related images have been clustered. Subject-name grouping also
does not guarantee all semantic aliases are removed; human review remains useful.

The knowledge corpus remains searchable in all conditions, including evidence
for test queries. Holding out a query/training group does not require removing
its legitimate knowledge documents from a retrieval index. The claimed split is
record/image-group held-out for these trained rerankers, not a guarantee that all
cultural facts or pretrained-model knowledge are unseen.

Evaluation questions and labels

validation_queries.json contains thirty newly authored factual questions, six
per dataset, plus six image queries. Their target groups are in the test fold.
The text questions are not copied verbatim from training anchors. Correct answers
and support excerpts were checked against the downloaded records. Image query
content was checked by directly inspecting the downloaded images.

Labels are source-verified positive targets. They are NOT an exhaustive semantic
annotation of every potentially relevant item in the complete corpus. Dataset
facts may themselves contain errors. Independent human expert review has not
been completed; human_reviewed remains false and no reviewer is invented.

A concrete data-quality issue was found: thali_ceremony.jpg shows a wedding but
its native QA asks about Pongal. The image query correctly describes a wedding
and records this mismatch. That native QA is not used as a factual text test case.

research/annotation_review.csv gives question, answer variants, positive source,
evidence, and editable review fields. A named reviewer can correct labels and
add relevant records/images using apply_annotation_reviews.py. Relevance should
be marked complete only after the relevant set has been genuinely checked.

All conditions retrieve one common candidate pool per question. For text, query
expansion is performed once and the exact phrasings are saved. The cross-encoder
keeps twelve distinct evidence references in the main experiment. Each condition
selects its best three and six from that same pool. A dataset hint does not
exclude any available dataset. The image pool is similarly shared across modes,
with identical image bytes counting as one image.

Text-only and image-associated cases

The case modality describes its labelled source: 24 text questions have text-only
sources and six have image-associated DRISHTIKON sources. Six additional queries
perform image retrieval only. All text conditions search the same five datasets;
text-only-source queries can still encounter image-associated candidates from
other sources. They are not artificially restricted to text-only datasets.

The default experiment enables available visual features in both trained models.
A --text_only validation run masks their image features and should be reported
as a separate ablation. CLIP image retrieval still needs real images in that run.
The final QA reader receives text only. Retrieved images are independent evidence;
this is not a reproduction of RetVQA's visual MI-BART answer generator.

Reader corrections and error handling

The reader searches only context-token positions, not question or special tokens.
It jointly selects valid start/end spans, enforces ordering and maximum length,
uses overlapping windows for longer contexts, and extracts using character
offsets. Empty answers cannot outrank valid answers. Exceptions are recorded with
reader_errors and are not silently converted into normal no-answer results.
Affected aggregate quality metrics are withheld when evaluation errors occur.
The same reader configuration and cached per-context results are used for all
conditions, so model comparisons do not use different reader behavior.

Indexed-content coverage

The copied index has 75,752 active documents, including report chunks. All active
source records have some indexed content. DOSA, SCALE and DIWALI have complete
character coverage. Four DRISHTIKON records are partial, with about 99.87% total
character coverage. Indian Cultural Dataset has 11 fully indexed records and 85
partial records, with only about 4.24% of its total characters indexed, because
very long rows were capped in the inherited index. Every record's measured
coverage and unmatched-chunk count is recorded. These gaps are disclosed, not
presented as complete corpus coverage. Rebuilding a full long-document index is
a separate substantial embedding operation; the existing index is retained for
this matched comparison. Report dataset-search coverage separately from text-
content coverage. Searching all five datasets does not mean all words are indexed.

Metrics and timing

Precision@K = labelled relevant results in top K / requested K.
Recall@K = labelled relevant results in top K / supplied labelled relevant set.
Hit@K = whether at least one labelled relevant result appears.
MRR@K = mean reciprocal rank of the first relevant result, truncated at K.
nDCG@K = binary discounted cumulative gain divided by its ideal ordering.
Answer Exact Match and token F1 compare normalized predictions with accepted
answer variants; maximum credit is taken across those variants. Normalization
case-folds, removes ASCII punctuation and English articles, and collapses spaces.
Whitespace F1 does not establish semantic equivalence, especially across languages.
Missing labels remain unavailable rather than zero. Duplicate hits earn no extra
credit. Text relevance uses record IDs, including long parent records. The separate
answer_evidence_hit metric checks that the selected labelled context actually
contains an accepted answer, since finding another chunk of the same record may
not supply the answer. Image labels resolve to actual file-content hashes.

The matrix reports overall results, per dataset, and by source modality. Stage
costs distinguish common retrieval, frozen fusion-feature extraction, reranker
inference, and selected reader context costs. Reader results are extracted once
per query and shared; reader_ms is the sum of measured per-context costs in each
selected subset, not the low wall time of replaying already cached answers.
Model loading/startup is excluded. The first image query includes image-pool
initialization; query-expansion cache hits are recorded. These laptop timings are
observations, not a universal speed benchmark.

paired_differences.csv reports descriptive 95% paired bootstrap intervals for
MRR and answer F1 using 1,000 resamples and seed 42. The intervals apply to this
small labelled question sample. A single training seed and weak sampled negatives
cannot support a broad claim of MoE superiority. Larger independently reviewed
questions, complete relevance judgements, and repeated training seeds strengthen
that claim. Factual answers from an English reader need separate multilingual
validation even when the retrieval encoder is multilingual.
